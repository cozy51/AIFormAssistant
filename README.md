# AI帳票アシスタント

Google Drive上のPDFを根拠に、製造業・機械設計向け帳票の文章を項目ごとに作成する日本語Webアプリです。過去実績は文体の参考、注意事項は記入ルール、今回案件の資料は事実情報として区別します。Excel・Wordへの貼り付けは手動です。

## 技術・構成

Next.js App Router / React / TypeScript / Tailwind CSS / shadcn/ui方式のButton（Radix Slot + CVA）/ Google Drive API / Google OAuth 2.0 / Google Gen AI SDK `@google/genai` / PDF.js / pdf-lib / Dexie・IndexedDB / Zod。

外部永続DBは使用しません。OpenAI API、Supabase、Firebase、Ollamaへの依存はありません。DriveのフォルダIDによる管理も行いません。

- `src/app/api/auth/`：OAuth認証、PKCE・state、有効期限、暗号化HttpOnly Cookie
- `src/app/api/drive/`・`pdf/`：PDF取得・メタデータ・ページ数・解析
- `src/app/api/analyze/`：テンプレート抽出、実績分析、ルール対応・競合抽出
- `src/app/api/generate/`：項目別生成、原本の更新確認、参照元照合
- `src/components/`：ダッシュボード、テンプレート、案件・文章編集、設定
- `src/lib/schema.ts`：ドメインと入出力のZodスキーマ、参照照合、文字数
- `src/lib/db.ts`：端末内DB、バックアップ、トランザクション付きインポート
- `src/lib/server.ts`・`ai.ts`・`drive.ts`：認証・アクセス制御・外部API
- `tests/`：外部サービスをモックした単体・APIテスト
- `e2e/`：Chromiumによる実画面操作（外部AI・認証はモック）

## 必要な環境とインストール

Node.js **24以上**、npm、Google Cloudプロジェクト、Gemini APIキー、モダンブラウザ（IndexedDB、Clipboard対応）が必要です。

```sh
npm ci
cp .env.example .env.local
# .env.local を編集して必要な値を設定
npm run dev
```

ブラウザで起動したアプリを開きます。開発ポートは3000です。本番は `npm run build` → `npm start`。`npm run typecheck`、`npm run lint`、`npm test` で検証します。クラウドの各タスクは分離済みなので既存チェックアウトを使用し、ユーザーが求めない限り追加のGit worktreeは作成しません。

このクラウド環境ではTurbopack内部プロセスのポートが制限されるため、開発・ビルドに標準のWebpackを使用しています。起動スクリプトの `--use-env-proxy` はNode.js 24のプロキシ対応を有効にし、既存のHTTPS_PROXY / HTTP_PROXY / NO_PROXYとCA設定を継承します。TLS検証を無効化しないでください。`npm ci` のpostinstallで、インストールしたPDF.jsと一致するWorkerを `public/` に配置します。

## Google Cloud・Google OAuth設定

1. Google Cloud Consoleでプロジェクトを作成し **Google Drive API** を有効にします。
2. Google Auth PlatformでOAuth同意画面を設定します。社内利用なら組織内、テスト中ならテストユーザーに利用者を追加します。
3. データアクセスに `openid`、`email`、`https://www.googleapis.com/auth/drive.readonly` を設定します。
4. 「ウェブアプリケーション」型OAuthクライアントを作成します。リダイレクトURIに `http://localhost:3000/api/auth/callback`、本番は `https://実ホスト/api/auth/callback` を登録します。
5. クライアントIDとシークレットをサーバー環境変数へ設定します。`APP_URL` とリダイレクトURIのオリジンを一致させます。
6. `APP_ALLOWED_EMAILS` に許可するGoogleメールアドレスをカンマ区切りで指定します。未設定の場合は利用を許可しません。
7. 設定画面からGoogleに接続します。

ファイルIDで指定された既存ファイルへアクセスするため **drive.readonly** を採用しています。`drive.file` はPicker等で選択・承認されていない既存ファイルを読めないため、この仕様のID直接指定には適合しません。読み取り専用権限でもGoogleの制限付きスコープに該当するので、外部公開時はGoogleの審査やセキュリティ評価要件を確認してください。フォルダ一覧を取得せず、ユーザーが登録したIDだけを読みます。共有ドライブにも対応します。

トークンはAES-256-GCMで暗号化したHttpOnly・SameSite=Lax Cookieにのみ保存します。本番HTTPSではSecure属性を付けます。アクセストークンは必要時に更新し、アプリセッションは7日で失効します。認証情報はブラウザのIndexedDB・JSON・ログに保存しません。「接続解除」はこのブラウザのセッションを削除します。Google側の承認を取り消す場合はGoogleアカウントの接続済みアプリ設定も操作してください。

## Gemini API設定

Google AI StudioでAPIキーを作成して、サーバーの `GEMINI_API_KEY` に設定します。キーを `NEXT_PUBLIC_` 環境変数に入れないでください。初期モデル候補は `gemini-2.5-flash` です。`GEMINI_MODEL` または設定画面で変更できます。設定画面の「モデル一覧を取得・接続確認」は、当該APIキーで利用可能なモデルを問い合わせ、preview / experimental等を除外します。モデルの提供状況はGoogleで変更されるため、利用可能な安定版を選択してください。この作業環境にAPIキーがないため、初期モデルの実接続・現在の提供可否は未検証です。

PDFの解析と生成のたびに、外部AIへ送信することを確認します。所属組織の機密情報ルール・Googleの利用規約・課金設定を事前に確認してください。20ページ以下かつBase64の増加を考慮したサイズの単位へPDFを分割します。単一ページが大きすぎる場合は圧縮を案内します。大きなPDFの解析は複数回のAPI呼び出しを伴います。

## 環境変数

`.env.example` を参照してください。認証情報の実値をGitに登録しないでください。

| 名前                   | 用途                                                 |
| ---------------------- | ---------------------------------------------------- |
| `GOOGLE_CLIENT_ID`     | Google Web OAuthクライアントID                       |
| `GOOGLE_CLIENT_SECRET` | OAuthクライアントシークレット                        |
| `GEMINI_API_KEY`       | サーバー専用Gemini APIキー                           |
| `GEMINI_MODEL`         | 初期モデル。保存済みブラウザ設定が優先               |
| `APP_URL`              | アプリのオリジン。末尾パスなし。本番はHTTPS          |
| `APP_ALLOWED_EMAILS`   | 許可メールアドレス。カンマ区切り                     |
| `SESSION_SECRET`       | 32文字以上のランダム文字列。Cookie暗号化・解析署名用 |

`SESSION_SECRET` は `openssl rand -base64 48` などでローカル生成し、安全な設定機構から投入します。ローカル暗号化に使うため、ネットワークプロキシのダミー値では動きません。値の変更は既存セッションと解析署名を無効にします。

クラウドの通信先は `accounts.google.com`、`oauth2.googleapis.com`、`openidconnect.googleapis.com`、`www.googleapis.com`、`generativelanguage.googleapis.com` を必要に応じて許可します。Googleログイン画面は利用者のブラウザで開かれます。既存のプラットフォーム認証・プロキシは上書きしないでください。

## 使い方

1. **設定**でGoogleへ接続し、Geminiのモデル一覧取得で接続を確認します。
2. **帳票テンプレート**を作成します。設計変更申請書など、自由な名前を指定できます。
3. 過去実績PDFと注意事項PDFを、それぞれ個別の**ファイルIDまたは共有URL**で登録します。`https://drive.google.com/file/d/ファイルID/view`、`open?id=ファイルID` を受け付けます。PDFの公開設定は不要で、ログインユーザーに閲覧権限が必要です。
4. 各PDFの「解析・更新確認」で解析します。同じID・更新日時ならキャッシュを使い、「再解析」で原本から再処理します。「PDF.jsで本文確認」はブラウザ内でテキスト層を抽出します。スキャン・表・図の内容理解はサーバー経由のGeminiで行い、不確実な読み取りを表示します。
5. **PDFから項目・ルールを抽出**し、候補を確認して編集欄へ取り込みます。項目名・順序・説明・ルール・目標字数・参考文・追加指示を修正できます。実績の平均・最小・最大文字数、文体・用語・粒度と意味的な対応を確認し、対応を「確認した」にします。
6. 注意事項の適用先を帳票全体または個別項目に設定し、内容・適用先を確認します。競合がある場合はルールを修正して解消を明示します。未確認の対応や未解決の競合があると生成を止めます。AIによる競合検出は完全ではないため、原本も確認してください。
7. テンプレートを**保存**します。複製・削除・項目の追加削除・上下移動も可能です。
8. **新しい案件を作成**し、保存済みテンプレートを選択します。作成時のテンプレートと実績・注意事項PDFを案件へ引き継ぎます。後から元テンプレートを変更・削除しても既存案件の定義は維持されます。
9. 「案件情報・登録資料」で今回案件のPDFを登録・解析し、追加指示を入力します。
10. 全項目または選択項目の候補を生成します。項目ごとに参照元・不足情報・警告を確認し、**この候補を採用**します。直接編集と確定・未確定の切り替えができます。
11. 短くする・詳しくする・箇条書き・技術文書らしく・実績に近づける・注意事項再確認、または自由な追加指示で新候補を生成します。現在の文章を無断で置換しません。
12. コピーしてExcel・Word等へ貼り付けます。履歴から案件を開き直して編集を続けられます。編集開始時や候補採用時に保存した以前の文章へ復元できます。

参照元はファイルID・ページ・短い抜粋を解析済み本文・項目・表・図と照合し、一致しないものを除外します。原本を更新していたり解析署名がない場合は再解析が必要です。照合はAIによる読み取り結果との一致を検証するもので、文章全体の正しさを保証しません。手動編集後は根拠との対応を再確認してください。

## 保存とバックアップ

端末内のIndexedDBにテンプレート・PDF情報・解析キャッシュ・実績分析・注意事項・案件・生成候補・編集履歴・確定状態・設定を保存します。案件の文章編集と確定操作は自動保存、テンプレートと設定は保存ボタンで確定します。複数端末間の自動同期はありません。共用端末やブラウザプロファイル内では保存データが共通になるため、利用者ごとにOS/ブラウザプロファイルを分けてください。

設定画面からJSONをエクスポートできます。機密情報に該当するPDF本文・生成文章は含まれるため安全に保管してください。APIキー・Googleトークン・解析署名はエクスポートしません。インポートはZod検証後に件数・重複件数を表示し、明示確認後にトランザクションで保存します。既存保持/重複置換を選択できます。復元したPDF解析結果は生成前に再解析が必要です。

ブラウザのデータ削除・ストレージ不足・プライベートモード・端末故障に備え、定期的にバックアップしてください。全データ削除は確認ダイアログ付きです。PDFのDrive原本は変更しません。別タブで同じ案件を同時編集すると最後の保存が優先されるため、同じ案件は1タブで編集してください。

## テスト

```sh
npm run typecheck
npm run lint
npm test
npm run build
# Chromium導入済みならそのパスを設定（この環境は /usr/bin/chromium）
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

Playwrightのテストは外部サービスの応答をモックし、本物のブラウザでテンプレート/案件作成、候補採用、編集、コピー、確定、再読込、JSONインポート/エクスポート、レスポンシブ・ダークモード、未認証API拒否を確認します。デフォルトは本番ビルドをポート3100で起動します。テスト用Originもそのポートに合わせます。ブラウザ未導入ならPlaywrightの公式手順でChromiumを導入し、実行ファイルのパスを指定してください。

実サービスとの接続テストは、環境変数を設定し、Googleログイン→モデル一覧取得→権限のある実績/注意/今回PDF登録→解析→項目抽出・確認→生成→引用元を原本照合、の順で行ってください。鍵や資料のない環境ではモック結果だけで実接続成功とは判断しません。

## よくあるエラーと制約

- **Google未設定/ログインできない**：OAuth ID・secret・許可メール・APP_URL・リダイレクトURI・テストユーザー・Drive API有効化を確認します。
- **ファイルが見つからない/権限不足**：Googleアカウントの共有権限とファイルIDを確認し、設定から再認証します。PDF以外・ゴミ箱・パスワード保護・破損PDFは登録できません。
- **Gemini未設定/認証失敗/モデルがない**：サーバーのAPIキーとモデル提供状況・API利用権限を確認します。
- **利用制限**：一時的な429/500/503は最大3回、待機時間を増やして再試行します。それ以上は課金・クォータ確認、時間をおいて再実行します。
- **AI形式不正/参照不一致/読み取り失敗**：再解析または鮮明な資料へ差し替え、原本を人が確認します。スキャン・表・数値の認識精度は資料とモデルに依存します。
- **未確認のルール・競合**：テンプレートで対応とルールを確認して保存し、新規案件を作成します。既存案件はスナップショットを保持します。
- **保存失敗**：ブラウザの空き容量・保存許可を確認し、画面が残っている間にバックアップします。
- **ネットワーク切断**：接続とクラウド許可ドメインを確認します。未検証の証明書を許可する回避策は使用しません。
- **処理時間**：AI処理はサーバーで行います。ホスト側のリクエスト実行時間は最大300秒を想定しており、長いPDFは小分けにしてください。1 PDF最大40MB/300ページ、1回の生成は最大30 PDF、送信JSON最大3MBです。標準設定は20MB/100ページです。
- **濫用防止**：OAuth許可リスト・Origin検証・利用者単位のプロセス内レート制限（通常90回/分、AI12回/分）。複数プロセスで運用する際はロードバランサ/APIゲートウェイ側にも全体のレート制限とGoogleクォータを設定してください。外部永続DBは用いません。
- **本文の保存先**：原本PDFバイナリは永続保存せず処理メモリ内で扱います。解析テキストは利用者のIndexedDBに保存し、PDF/生成本文をアプリログへ出力しません。Geminiへの外部送信は発生します。
